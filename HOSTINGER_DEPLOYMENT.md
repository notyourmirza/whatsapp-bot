# WA Convo on Hostinger hPanel

## What caused the 503

The project is native ESM (`"type": "module"`) and `src/api/server.ts` uses top-level `await`. Hostinger's OpenLiteSpeed Node loader (`lsnode.js`) was trying to load `dist/api/server.js` with CommonJS `require()`, which fails with `ERR_REQUIRE_ASYNC_MODULE`.

This fix keeps the application ESM. `hostinger-bootstrap.cjs` is a small CommonJS entry point that uses dynamic `import()` to load the compiled ESM server.

## hPanel settings

Use a Hostinger Node.js Web App with:

- **Node.js:** 20.x (18 or newer is supported)
- **Package manager:** npm
- **Application root:** repository root
- **Build command:** `npm run build:all`
- **Application startup file:** `hostinger-bootstrap.cjs`
- **Start command:** `npm start` if hPanel exposes a start-command field; otherwise the startup file above is sufficient

Do not use `dist/api/server.js` as the hPanel startup file. That is the ESM module that caused the loader error.

## Required environment variables

Set these in hPanel Environment Variables. Do not commit real values to GitHub.

```text
NODE_ENV=production
HOST=0.0.0.0
PORT=<the PORT assigned by hPanel, if hPanel requires one>
API_KEY=<long random secret>
CORS_ORIGIN=https://your-domain.example
CLIENT_COUNT=1
LOG_LEVEL=info
RATE_LIMIT_MAX=60
```

`PORT` is read by the server and takes precedence over `config/config.json`. `HOST=0.0.0.0` is required so the public proxy can reach the process. `API_KEY` protects the API routes; keep it secret.

Optional variables that are actually read by the code are `WEBHOOK_URL`, `POST_API`, `META_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN`, `VITE_API_URL`, and `VITE_WS_URL`. AI provider settings are stored in `config/config.json` or changed from the dashboard; the old commented `AI_*` names are not runtime environment overrides in this repository.

## Build and URLs

After deployment, open:

```text
https://your-domain.example/
https://your-domain.example/health
https://your-domain.example/dashboard/
```

The root URL intentionally returns a JSON service description. It is not the dashboard. The dashboard is served from `/dashboard/` after `dashboard/dist` has been generated by `npm run build:all`.

The dashboard WebSocket now uses the current browser origin automatically. Therefore HTTPS uses `wss://your-domain.example/ws`; local HTTP uses `ws://localhost:<port>/ws`. `VITE_WS_URL` can still override this for a separately hosted API.

## WhatsApp connection

First verify `/health` and `/dashboard/`. Only then open Dashboard → Clients and initialize a client to display the QR code. Keep the generated `.auth/`, `data/`, and `logs/` directories persistent across restarts; otherwise linked WhatsApp sessions and local data may be lost.

Hostinger shared Node hosting may suspend or restart applications and may not be suitable for an always-on Baileys connection. If the process is regularly suspended, use a VPS or another persistent Node host. Do not connect WhatsApp until the app stays running reliably.

## Security

Rotate any API key or webhook secret that was previously committed to a public repository. The deployment archive excludes the repository's local `config/config.json` so existing secrets are not redistributed. Create the production config through hPanel variables and the dashboard instead.
